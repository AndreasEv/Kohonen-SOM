1. Introduction

The data are the letters of Assignment 2: 20,000 images of the 26 capital letters, made by Frey and Slate (1991) from 20 distorted fonts and reduced to 16 integer features in 0–15 (box size and position, ink moments, edge counts). I keep the same split: the first 16,000 patterns for training, the last 4,000 for testing. The task is to group the letters with a Kohonen Self-Organizing Map (SOM) and measure how well the groups match the real letters.

A SOM is a 2-D grid of neurons, each with a weight vector in the 16-D input space. For every input the closest neuron wins, and the winner and its neighbours on the grid move towards the input. Over many passes the grid folds into the data, so neighbouring neurons respond to similar inputs: the 16-D data are drawn as a 2-D map that keeps their topology.

Unlike back propagation in Assignments 1 and 2, there is no teacher: no target, no error to descend. The letter is never seen in training; it is used only afterwards to name each neuron and to score the test set. A good score therefore means the letters really form separate groups in feature space.

2. Solution design and reasoning

Grid. A square 20×20 grid (400 neurons) gives about 15 neurons per letter, enough for each letter to split into sub-groups for its fonts, while each neuron still sees about 40 of the 16,000 patterns. 10×10 (4 per letter) seemed too coarse; Section 4 compares 10×10, 15×15 and 20×20. I chose a square topology because the grid distance is then the plain Euclidean distance between (row, column) positions, as in the lecture's neighbourhood formula.

Normalisation. Each feature is min-max scaled to [0, 1], x′ = (x − min)/(max − min), with min and max from the training set only; the test set uses the same values and is clipped to [0, 1] (feature 16 is never below 1 in training but is 0 in some test patterns). The Euclidean distance is the whole algorithm, so every feature should have the same range and the same say in choosing the winner.

Initialisation. I implemented the lecture's random weights ("random": uniform in [0, 1)) and "sample", where each neuron starts as a random training pattern; both use the seed randomSeed. I chose "sample" because the data fill only a small part of the 16-D cube: before training the quantization error is 0.26 with "sample" against 0.83 with "random".

Algorithm. One epoch presents every training pattern once, in a new random order:

normalise data; initialise weights (seeded)
for t = 0 .. T-1:                 # T = maxIterations
    eta, sigma = eta(t), sigma(t)
    for x in shuffled training set:
        c = winner of x           # smallest ||x - w_j||
        for every neuron j:
            w_j += eta * h_cj * (x - w_j)
    QE on training and test set
label neurons; test accuracy

Formulas (lecture L6). Winner: smallest dj = Σi(xi − wij)². Gaussian neighbourhood: hcj(t) = exp(−‖rc − rj‖² / 2σ²(t)), with r the grid position; I preferred it to the bubble function because it fades smoothly instead of cutting off. Update after every pattern: wij(t+1) = wij(t) + η(t) hcj(t)[xi − wij(t)]. Error (quantization error): QE = (1/N) Σp ‖xp − wc(p)‖, on both sets after every epoch.

Decay of η and σ. The lecture decays the radius exponentially, σ(t) = σ0 exp(−t/τ), but the learning rate linearly, η(t) = η(0)(1 − t/T). I decay both exponentially between an initial and a final value:

η(t) = η0(ηT/η0)t/(T−1),   σ(t) = σ0(σT/σ0)t/(T−1)

This is the lecture's exp(−t/τ) with τ = (T−1)/ln(σ0/σT), so the last epoch uses exactly the final value. The lecture splits training into a clustering stage with a large η and a fine-tuning stage with a small one. With exponential decay η falls below 0.1 after 41 of 100 epochs, leaving most of the run for fine tuning; the linear form stays above 0.1 until epoch 80, and it reaches η = 0 at t = T, so the last epoch would learn nothing. Decaying both on the same schedule also keeps the neighbourhood from staying wide while the steps are already tiny. Figure 1 matches this: the error is noisy until about epoch 40, smooth after.

Labels. After training each neuron gets the most frequent letter among the training patterns it wins (ties: alphabetically first); a neuron with no patterns gets “–”. A test pattern is correct if its winner has its letter, so landing on “–” is wrong.

Difficulties. The assignment's parameter file has only an initial radius, and my first version decayed σ to 1. With a Gaussian, σ = 1 still moves the winner's direct neighbours by e−0.5 ≈ 0.61 of its step, so every neuron stayed an average of its neighbourhood: 55.8% accuracy and a final QE (0.281) worse than the untrained map. I added the parameter finalRadius = 0.5 (neighbour weight e−2 ≈ 0.14), which raised accuracy to 67.65%, and initMethod (sample | random). Speed was the other problem: each pattern updates all 400 neurons, so the update is vectorised with numpy (about 1.3 s per epoch) and the experiments run four at a time.

3. Implementation

Python 3 with numpy (matplotlib only for plots), one file per role: parameters.py (reads parameters.txt from the current folder), data.py (loading, normalisation), som.py (grid, initialisation, winner, neighbourhood, update, decay, QE), training.py (epochs), clustering.py (labels, accuracy), results.py (output files), plots.py, experiments.py and main.py. Over 160 unit tests check each formula against hand-computed values. On a synthetic set of four tight Gaussian clusters on a 5×5 map, 25 epochs bring the QE from 0.25 to 0.022, each cluster gets its own neurons near its centre, and the test accuracy is 100%. Scrambling the training letters leaves the weights and results.txt identical, so the labels are never used in training.

5. Analysis and discussion

The map. Figure 2 has clear regions whose neighbours make sense by shape: a W block on the right with M and N beside it (wide letters, many vertical strokes); P, F and T along the top (ink at the top), with Y and V next to T; the round O, Q, G and C in the bottom middle; the narrow L, I and J on the left next to the A block. The commonest test errors follow these neighbourhoods: H→N (31), S→Z (30), R→B (26), H→K (25), G→O (22) and T↔Y (22/21), letters whose features really overlap. The SOM never sees labels, so it has no reason to draw a border between them. H is the extreme case: its 12 neurons are scattered over the map rather than forming a region, so it reaches only 21.2%.

Empty neurons. 8 of the 10 lie on the left edge between regions (e.g. between the L column and the A block), where the grid stretches across a gap in feature space. They mark separation between groups rather than a fault; only one test pattern landed on one.

Parameters. Grid size matters most: 46.6%, 58.9% and 67.7% for 10×10, 15×15 and 20×20, since 100 neurons cannot hold 20 fonts of 26 letters. Next is the final radius: ending at σ = 1 costs twelve points (Section 2), while the initial radius, the initial η and the initialisation each change the result by under one point, inside the seed spread of Table 3 (66.4–67.7%). Whatever the start, the wide early neighbourhood pulls the map into the data (in epoch 1 the QE drops from 0.83 to 0.50 with random weights and rises from 0.26 to 0.51 with samples), and every run ends with the same fine tuning at η = 0.01.

What I would change. Accuracy is still rising with grid size and Figure 1 is still falling at epoch 100, and training (70.3%) and test (67.65%) accuracy are close, so I would try a larger map (25×25 or 30×30) and more epochs, then a hexagonal grid. For reference, the supervised network of Assignment 2 reached 84.2% on the same split.

6. Conclusions

A 20×20 SOM trained without labels puts 67.65% of unseen letters on a neuron of their own letter (67.03 ± 0.49% over five seeds) and places similar shapes next to each other. The end of training matters more than the start (final radius and map size dominate), the error can rise during the ordering stage without anything being wrong, and the SOM's mistakes are the letters whose shapes really overlap.
